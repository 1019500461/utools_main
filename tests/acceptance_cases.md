# 登录与角色管理验收用例

## 执行前置条件

- 后端已启动：`uv run python run.py`
- 前端已启动：`cd web && corepack pnpm dev`
- `.env` 已配置 PostgreSQL 连接和 `SECRET_KEY`
- 首次启动后系统已初始化默认账号：`admin / 123456`

## 需求符合度用例

| ID | 场景 | 步骤 | 预期结果 |
| --- | --- | --- | --- |
| REQ-001 | 未登录访问后台 | 打开 `/system/role` | 自动跳转到 `/login` |
| REQ-002 | 登录页输入 | 打开 `/login`，检查用户名、密码输入框和登录按钮 | 页面可输入，默认提示账号密码可见 |
| REQ-003 | 登录成功 | 使用 `admin / 123456` 登录 | 跳转到 `/system/role`，看到角色管理页面 |
| REQ-004 | 角色列表 | 登录后进入角色管理 | 表格加载，至少包含初始化角色 |
| REQ-005 | 搜索角色 | 输入 `管理员` 并查询 | 表格只展示匹配角色或空结果，不报错 |
| REQ-006 | 新建角色 | 点击“新建角色”，填写唯一名称并保存 | 弹窗关闭，列表出现新角色 |
| REQ-007 | 编辑角色 | 点击新角色“编辑”，修改描述并保存 | 列表描述更新 |
| REQ-008 | 权限抽屉 | 点击“设置权限” | 抽屉打开，包含“菜单权限”和“接口权限”两个 Tab |
| REQ-009 | 保存权限 | 勾选/取消权限后点击保存 | 提示保存成功，重新打开仍能读取已保存数据 |
| REQ-010 | 删除角色 | 删除测试角色并确认 | 列表不再出现该角色 |
| REQ-011 | 退出登录 | 点击顶部“退出登录” | 清除 token，跳转回 `/login` |

## 参考项目一致性用例

| ID | 对照点 | 当前项目预期 | 参考项目来源 |
| --- | --- | --- | --- |
| REF-001 | 登录主流程 | 用户名、密码、登录按钮，登录后进入后台 | `web/src/views/login/index.vue` |
| REF-002 | 登录接口 | `POST /api/v1/base/access_token` 返回 `access_token` | `web/src/api/index.js` |
| REF-003 | 角色列表接口 | `GET /api/v1/role/list` 支持 `page`、`page_size`、`role_name` | `app/api/v1/roles/roles.py` |
| REF-004 | 角色增删改 | 页面提供新增、编辑、删除操作 | `web/src/views/system/role/index.vue` |
| REF-005 | 权限设置 | 角色行提供“设置权限”，抽屉展示菜单/API 权限树 | `web/src/views/system/role/index.vue` |
| REF-006 | 菜单/API 数据 | 权限抽屉分别调用菜单列表、API 列表和角色授权接口 | `web/src/api/index.js` |

## 已知差异

- 当前实现是最小可用版本，没有复刻用户管理、菜单管理、API 管理、部门、审计、动态路由全量能力。
- 当前页面用 Tailwind CSS 重写样式，不使用参考项目的 UnoCSS 原子类。
- 当前一致性目标是交互结构和接口契约一致，不做像素级一致。
