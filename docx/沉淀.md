# 基金/ETF 监控模块沉淀

更新时间：2026-05-26

## 1. 背景与目标

本次新增基金/ETF 监控模块，用于录入关注标的、同步历史行情、计算相对历史高点的回撤，并在触及预设观察点时通过邮件提醒。

核心目标：

- 后端新增独立 `etf` 业务模块，接口统一挂载到 `/api/v1/etf/*`。
- 数据库复用当前 PostgreSQL，不新建物理数据库。
- 新增 `etf_history`、`etf_monitor` 两张 ETF 相关表。
- 历史行情使用前复权数据。
- 前端提供标的列表、详情设置、手动同步入口。
- 通知邮箱由个人中心配置，SMTP 发件配置由 Render 后端环境变量提供。
- 真实环境部署后，使用本机非项目虚拟环境的 Python Playwright 校验页面和交互。

## 3. 数据库设计

### 3.1 ETFHistory

表名：`etf_history`

用途：存储 ETF/基金历史日 K 行情。

字段：

- `id`
- `code`
- `date`
- `open`
- `close`
- `high`
- `low`

约束：

- `(code, date)` 联合唯一。
- 批量写入时使用 `bulk_create(..., ignore_conflicts=True)`，重复数据忽略。

### 3.2 ETFMonitor

表名：`etf_monitor`

用途：存储用户关注标的和回撤提醒参数。

字段：

- `id`
- `code`
- `name`
- `is_active`
- `time_range`
- `x_drop`
- `y_step`
- `current_stage`
- `last_checked_at`
- `last_alert_at`
- `created_at`
- `updated_at`

当前限制：

- `code` 当前是全局唯一。
- 还没有按用户隔离关注列表。

## 4. 技术方案

### 4.1 行情数据源

当前不使用 AKShare，避免依赖体积过大。

实现方式：

- 使用轻量 `httpx` 直接请求公开行情接口。
- 东方财富作为主要数据源。
- 历史日 K 要求使用前复权数据。
- 对部分行情场景保留腾讯接口兜底。

设计原则：

- 接口失败时抛出明确错误，不假装同步成功。
- 节假日或非交易日接口无数据时允许安全退出。
- 列表页不再为每行请求实时行情，避免页面非常慢。

### 4.2 同步策略

初始化同步：

- 前端新增标的时调用 `/api/v1/etf/create`。
- 后端检测本地 `etf_history` 是否已有该代码数据。
- 如果没有数据，按 `time_range` 拉取 3 年、5 年或成立以来历史日 K。

增量同步：

- `/api/v1/etf/sync` 支持同步单个标的或当前监控列表。
- 根据本地最新日期计算断档天数。
- 请求窗口按 `N + 3` 天动态扩大，降低断档风险。
- 周末跳过；工作日接口无数据时安全退出。

列表性能优化：

- 列表页当前只读取本地最新两根日 K。
- 当前价格使用最新收盘价。
- 今日涨跌幅由最新两根日 K 计算。
- 避免列表页逐标的请求实时行情导致加载慢。

### 4.3 回撤计算

核心逻辑：

- 按 `time_range` 计算统计区间。
- 查询统计区间内 `MAX(high)` 作为 `peak_price`。
- 如果标的历史不足 3 年或 5 年，自动按已有全量历史计算，并返回轻量提示。
- 当前回撤：

```text
(peak_price - current_price) / peak_price
```

详情页会展示：

- 当前价格
- 区间高点
- 触发价格
- 当前回撤
- K 线图
- Peak 红色标线
- Trigger 绿色标线

### 4.4 监控状态机

监控入口：

- 后台轻量 `asyncio` 循环。
- 手动接口：`POST /api/v1/etf/monitor/run`。

触发时段：

- 周一至周五 `09:35 - 11:30`
- 周一至周五 `13:00 - 15:01`

状态机：

- `is_active = false` 时跳过。
- 当前价格创新高或回撤小于等于 0 时，`current_stage` 复位为 0。
- `current_stage = 0` 且回撤达到 `x_drop`，触发第 1 级观察点。
- `current_stage > 0` 时，下一条触发线为 `x_drop + current_stage * y_step`。
- 触发后 `current_stage += 1`。
- `last_alert_at` 用于防重复和排查。

### 4.5 邮件通知方案

SMTP 发件配置放在 Render 后端环境变量：

```text
SMTP_HOST=smtp.xxx.com
SMTP_PORT=587
SMTP_USER=your-sender@example.com
SMTP_PASSWORD=邮箱 SMTP 授权码或密码
SMTP_FROM=your-sender@example.com
SMTP_TLS=true
SMTP_TO=fallback-recipient@example.com
```

接收邮箱：

- 页面「个人中心」配置当前用户通知邮箱。
- 后端接口：`POST /api/v1/base/profile`。
- 邮件发送时优先使用系统内激活超级用户邮箱。
- 如果系统没有可用用户邮箱，则回退到 `SMTP_TO`。

邮件文案：

- 使用 HTML 邮件。
- 使用中性合规文案：量化策略、观察点、偏离度。
- 避免高频出现敏感金融词。

当前限制：

- 还没有按 ETFMonitor 归属用户发送给不同用户。
- 当前更接近系统级通知邮箱。

## 8. 已知问题与限制

- Render 免费实例休眠时，首次请求会慢。
- 列表页使用本地最新日 K，不是严格实时价。
- `etf_monitor.code` 当前全局唯一，还不支持多用户分别关注同一标的。
- 邮件接收人当前优先取超级用户邮箱，不是按每个 ETF 监控配置的创建人发送。
- 邮件发送没有页面上的测试发送按钮。
- 没有独立迁移系统，当前依赖 Tortoise `generate_schemas(safe=True)` 自动建表。
- ECharts 打包体积较大，ETF 页面 chunk 超过 Vite 默认提示阈值。
